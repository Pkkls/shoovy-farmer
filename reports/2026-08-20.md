shoovy.wtf answered **429 `rate limited`** (12-byte `text/plain`, `x-railway-edge`, no

short timeout fails on first contact regardless. Use 60 s when the site returns.

Discriminating test for the day it recovers: fire a small burst and see whether the 429
clears on a predictable timer. A limiter aimed at callers behaves like a timer; a sick
backend does not.

## The binding constraint is availability, and it is not one number

- Trivial read succeeds with p = **0.158** (`infra:availability`, n=19, `uptime.py`).
- A player command actually gets processed with p = **0.038** (n=52, `analyze_chat.py`) —
  a read landing does **not** guarantee an action lands.
- Chained calls collapse fast: 2 calls = 0.025, 3 calls = 0.0039 (`infer.py`).
- Longest usable streak observed: **2 requests** before a 429.

This kills the old multi-poller design (trader 240 req/h + collector + dashboard, three
independent streams). The correct shape is one shared client with one global token bucket;
`client.py` is that serialization point. Recorded, not yet rebuilt.
